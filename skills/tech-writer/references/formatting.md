# 포매팅과 코드 예제

초안의 목록·표·코드·경고를 다듬을 때와, 출력 형식(Markdown, Confluence, HTML)에 맞출 때 이 파일을 읽는다.

## L-1 순서가 있으면 번호 목록, 없으면 글머리 목록

따라 해야 하는 절차는 번호 목록으로 쓴다. 순서와 상관없는 대등한 항목은 글머리 목록으로 쓴다. 문장 속에 "먼저 ~하고, 그다음 ~한 뒤"로 이어 쓴 절차는 번호 목록으로 푼다.

왜: 목록의 모양이 곧 순서가 중요한지를 알려 준다. [S1]

## L-2 한 단계에는 한 동작만 둔다

절차의 각 단계에는 독자가 할 동작 하나를 쓴다. 분기(환경별, 조건별)가 있으면 단계 안에 섞지 말고 하위 단계나 별도 단계로 나눈다. 버튼·메뉴·필드 이름은 화면에 보이는 그대로 작은따옴표나 굵게 표시한다.

왜: 한 단계에 동작이 둘이면 독자가 하나를 빠뜨린다. [S7]

## L-3 목록은 필요한 곳에만, 중첩은 한 단계까지

기본은 문장으로 쓴다. 항목을 나열하거나 단계를 보여 줄 때만 목록을 쓴다. 목록 안에 목록은 한 단계까지만 둔다. 더 깊어지면 표나 별도 섹션으로 바꾼다.

왜: 모든 것을 목록으로 쪼개면 문장 사이의 관계(이유, 조건)가 사라진다. 깊은 중첩은 구조를 숨긴다. [S11]

## L-4 비교와 속성은 표로 쓴다

여러 대상을 같은 기준으로 비교하거나, 항목마다 같은 속성(이름, 타입, 필수, 기본값, 설명)을 가지면 표로 쓴다. 매개변수 표의 열 순서는 `이름 | 타입 | 필수 | 기본값 | 설명`으로 통일한다.

왜: 같은 기준을 나란히 보여 주는 데는 표가 문장보다 빠르다. [S11, S2, S3]

## L-5 코드 블록은 언어를 지정해 설명 뒤에 둔다

모든 코드 블록에 언어(`bash`, `yaml`, `json`, `java`, `text` 등)를 지정한다(`lint_doc.py`가 오류로 잡는다). 코드 앞에 무엇을 하는 코드인지 한 문장을 쓴다. 독자가 바꿔야 하는 값은 `<대괄호>`나 대문자 자리표시자로 표시하고 바로 아래에 무엇으로 바꾸는지 쓴다.

왜: 언어 지정이 없으면 강조 표시가 사라지고 복사 실수가 늘어난다. 설명 없이 나온 코드는 독자가 역으로 해석해야 한다. [S3]

## L-6 경고와 강조 상자는 아껴 쓴다

경고 상자는 되돌릴 수 없는 작업, 보안, 데이터 손실처럼 정말 위험한 곳에만 쓴다. 한 화면에 상자가 둘 이상이면 하나로 줄이거나 본문으로 옮긴다. 상자 종류(참고, 주의, 경고)의 의미를 문서 안에서 일관되게 쓴다.

왜: 모든 것을 강조하면 아무것도 강조되지 않는다. [S11, S5]

## L-7 제목은 H1~H3으로 구조를 보인다

H1은 문서 제목 하나만 둔다. 본문은 H2, 그 아래는 H3까지 쓴다. 제목 수준을 건너뛰지 않는다(H2 다음에 바로 H4를 쓰지 않는다).

왜: 제목 수준이 곧 목차가 된다. 깊이가 넘치면 문서를 나눠야 한다는 신호다(structure.md E-3). [S11, S3]

## L-8 그림과 표가 많으면 캡션을 단다

문서에 그림·표가 다섯 개 이상이면 번호와 캡션을 단다. 그림 캡션은 그림 아래, 표 캡션은 표 위에 둔다. 본문에서는 "그림 2"처럼 번호로 가리킨다.

왜: 시각 자료가 많아지면 본문에서 어느 것을 가리키는지 헷갈린다. [S1]

## L-9 긴 부가 정보는 접거나 뒤로 보낸다

주된 흐름에 꼭 필요하지 않은 부가 설명, 긴 로그, 전체 설정 파일, 자주 묻는 질문은 접기(`<details>`)로 감추거나 문서 끝의 FAQ·부록으로 옮긴다.

왜: 주된 흐름이 끊기지 않아야 독자가 목표까지 간다. 필요한 사람은 펼쳐 본다. [S3]

## N-1 실행되는 예제와 결과를 함께 보인다

예제는 복사해서 실행하면 동작해야 한다. 입력만 보여 주지 말고 실행 결과(출력, 응답 본문, 반환값)를 함께 보여 준다. 실행에 필요한 사전 조건(환경 변수, 권한, 데이터)은 예제 앞에 쓴다.

왜: 실행되는 예제가 가장 빠른 설명이다. 결과가 있어야 독자가 자기 결과와 비교할 수 있다. [S2, S3]

## N-2 성공했는지 판단하는 기준을 쓴다

학습·how-to·런북의 마지막 단계 다음에는 "이렇게 보이면 성공"을 쓴다. 출력의 특정 줄, 상태 값, 대시보드 지표처럼 독자가 직접 확인할 수 있는 것이어야 한다.

왜: 확인 방법이 없으면 독자는 끝났는지 모른 채 다음으로 넘어가거나 같은 작업을 반복한다. [S3]

## N-3 단순한 예제에서 시작해 단계적으로 넓힌다

첫 예제는 가장 작은 동작 하나만 보여 준다. 옵션, 오류 처리, 실전 설정은 다음 예제에서 하나씩 더한다.

왜: 처음부터 모든 옵션이 들어간 예제는 핵심이 어디인지 보여 주지 못한다. [S3]

## N-4 잘못된 예와 오류 처리도 보여 준다

자주 하는 실수가 있으면 잘못된 예를 먼저 보이고 올바른 예를 이어서 보인다. API 예제에는 성공 응답과 함께 대표 오류 응답을 넣는다.

왜: 독자가 실제로 마주치는 것은 실패한 코드다. 실패 모습을 알면 자기 문제를 빨리 알아본다. [S3, S2]

## 형식별 차이

config `output.format`에 따라 같은 요소를 다르게 표기한다.

### Markdown (저장소 문서)

````markdown
> [!WARNING]
> 이 명령은 운영 데이터베이스의 테이블을 삭제합니다. 실행 전에 백업을 확인하세요.

<details>
<summary>전체 설정 파일 보기</summary>

```yaml
batch:
  chunk-size: 500
```

</details>

**표 1. 배치 설정 항목**

| 이름 | 타입 | 필수 | 기본값 | 설명 |
|---|---|---|---|---|
| `chunk-size` | int | 아니요 | 500 | 한 번에 처리할 주문 수 |
````

- 다이어그램은 mermaid 코드 블록으로 넣는다(GitHub·GitLab이 렌더링한다).
- 문서 간 링크는 상대 경로로 쓴다.

### Confluence

결과물은 Confluence 편집기에 붙여 넣거나 Atlassian MCP(Model Context Protocol)로 게시할 Markdown 원고다. Markdown에 없는 Confluence 요소는 아래 표기로 남긴다. GitHub 전용 문법(`> [!WARNING]`)은 쓰지 않는다. Confluence에서 그대로 인용문으로 보이기 때문이다.

| Confluence 요소 | 원고 표기 |
|---|---|
| 경고 패널 | `> **⚠️ 경고** ...` 바로 위 줄에 `<!-- confluence: warning panel -->` |
| 정보·참고 패널 | `> **ℹ️ 참고** ...` 바로 위 줄에 `<!-- confluence: info panel -->` |
| 목차 매크로 | `<!-- confluence: toc -->` (런북에는 넣지 않음) |
| 확장(접기) | `<!-- confluence: expand "제목" -->` ... `<!-- /confluence: expand -->` |
| 다이어그램 | `![그림 N. 설명](<문서 위치 기준 상대 경로>/<이름>.svg)` — 이미지 파일을 반드시 만든다. 예) `docs/runbook.md`에서 `docs/assets/runbook-1.svg`는 `assets/runbook-1.svg` |

- 맨 위에 개요 1~2문장, 그다음 구분선, 그다음 목차 매크로를 둔다. 런북처럼 첫 화면에 행동이 보여야 하는 문서는 목차 매크로를 넣지 않는다.
- 경고·참고는 정보·주의·경고 패널로 바꾼다. 아이콘과 색은 의미별로 하나씩만 쓴다.
- 접기는 확장(expand) 매크로로 바꾼다.
- 다이어그램은 `render-mermaid.sh`로 만든 SVG/PNG를 첨부한다. config `confluence_mermaid_macro: true`면 mermaid 매크로에 코드를 넣는다.
- Atlassian MCP로 직접 게시할 때는 사용자가 요청한 경우에만 하고, 게시 전 본문을 보여 준다.

### HTML (단일 파일)

- 하나의 `.html` 파일에 스타일과 다이어그램(SVG)을 모두 넣는다.
- 경고는 `<aside class="warning">`, 접기는 `<details>`로 쓴다.
- 복잡한 아키텍처는 archify가 만든 HTML을 같은 폴더에 두고 링크한다(visualization.md).
