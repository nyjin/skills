# 화자별 녹음 전사 (asr)

녹음 파일 하나를 화자별로 나눈 한국어 전사본(`.md`)과 데이터(`.json`)로 만든다. 모든 처리는 이 Mac 안에서 이뤄지며, 녹음과 전사본을 외부로 보내지 않는다. 이 스킬은 정확한 화자별 전사본까지만 책임진다. 요약이나 평가를 함께 요청받으면 전사를 마친 뒤 그 일은 다른 스킬에 넘긴다.

아래 명령의 `<스킬 디렉터리>` 는 이 스킬을 불렀을 때 표시되는 "Base directory for this skill" 경로다. 링크로 설치했든 플러그인으로 설치했든 그 절대 경로로 바꿔 쓴다(예: `~/.claude/skills/asr`).

- 스크립트: `<스킬 디렉터리>/scripts/`
- Python: `~/.local/share/asr/venv/bin/python` (스킬 전용 가상환경, 위치 고정)

## 1. 환경을 점검한다

```bash
bash "<스킬 디렉터리>/scripts/check_env.sh"
```

출력은 `KEY=VALUE` 줄이고, 마지막 줄 `STATUS` 로 다음 할 일을 정한다.
`MEM_WARNING=` 줄이 있으면 그 값(`메모리 <N>GB — 24GB 이상을 권장합니다. …`)을 한 번 알리고 그대로 진행한다. 막지 않는다.

- `STATUS=ready`: 2단계로 간다.
- `STATUS=missing`: `<스킬 디렉터리>/references/install.md` 를 따라 설치를 고지하고 동의를 받는다. 동의 없이는 설치하지 않고, 설치하지 않았으면 2단계로 가지 않는다.
- `STATUS=unsupported`: `이 스킬은 Apple Silicon(M1 이상) Mac 전용입니다. 현재 환경(<os>/<arch>)은 지원하지 않습니다.` 를 보여 주고 멈춘다. 설치도 전사도 하지 않는다. (`<os>`, `<arch>` 는 출력의 `OS=`, `ARCH=` 값)

## 2. 전사한다

```bash
~/.local/share/asr/venv/bin/python "<스킬 디렉터리>/scripts/transcribe.py" "<녹음 경로>" --cwd "$PWD"
```

- 경로에 공백이나 한글이 있을 수 있으니 반드시 따옴표로 감싼다.
- 실측으로 12분 녹음에 약 3분, 51분 녹음에 약 17분 걸린다. 몇 분 이상 걸릴 녹음은 Bash `run_in_background` 로 돌리고, 시작할 때 예상 시간을 알린다.
- 진행 상황(`조각 n/N 처리 중 …`)은 stderr 로, 요약 JSON 은 stdout 으로 나온다.
- 결과 파일은 녹음과 같은 폴더에 만든다. 그 폴더에 쓸 수 없거나 `~/Library` 아래(음성 메모 보관함 등)면 `--cwd` 폴더에 만든다. 같은 이름이 있으면 덮어쓰지 않고 `이름 (2)` 처럼 번호를 붙인다.
- 원본 녹음은 읽기만 한다.
- 종료 코드 2 는 입력·저장 오류다(파일 없음, 디코딩 실패, 결과 폴더에 쓸 수 없음 등). 저장할 폴더는 전사 전에 확인한다. stderr 메시지를 그대로 보여 주고 멈춘다.
- 종료 코드 3 은 전사 엔진 오류다. 대개 메모리 부족이다. stderr 메시지(다른 앱을 닫고 다시 실행, 그래도 같으면 메모리가 권장 24GB 보다 작음)를 그대로 보여 주고 멈춘다.

요약 JSON 의 키는 다음과 같다.

| 키 | 뜻 |
|---|---|
| `md`, `json` | 저장한 전사본과 데이터 경로 |
| `speakers` | `[{label, first_lines}]`. 번호순 화자 표시 이름과 첫 발언 |
| `enhanced` | 음량이 낮아 보정했으면 `{lufs_before}`, 아니면 `null` |
| `merged` | 목소리가 같아 합친 화자 쌍 `[{from_label, into_label, similarity}]` |
| `failed_ranges` | 인식에 실패한 구간 `[{start, end, reason}]` (초) |
| `no_speech` | 남은 발화가 하나도 없으면 `true` |
| `chunks` | 나눠 처리한 조각 수 |

## 3. 결과를 안내한다

요약 JSON 으로 아래 문안을 채운다. `[...]` 줄은 해당할 때만 넣는다.

```
전사를 마쳤습니다: <md 경로>
[보정 시] 녹음 음량이 매우 낮아(<lufs> LUFS) 보정본으로 분석했습니다. 원본은 그대로입니다.
[통합 시] 목소리가 같은 화자 <n>쌍을 하나로 합쳤습니다.
[실패 구간 시] 다음 구간은 인식에 실패했습니다: <구간들>
- 화자 1: "<첫 발언>"
- 화자 2: "<첫 발언>"
화자는 화자1, 화자2입니다. 이름을 바꾸려면 원하는 이름을 알려 주세요.
```

- 보정: `enhanced` 가 `null` 이 아니면 넣고, `<lufs>` 는 `enhanced.lufs_before` 다.
- 통합: `merged` 가 비어 있지 않으면 넣고, `<n>` 은 `merged` 의 길이다.
- 실패 구간: `failed_ranges` 가 비어 있지 않으면 넣고, 각 구간을 `HH:MM:SS–HH:MM:SS` 로 적는다. 녹음 일부를 알리지 않고 빠뜨리면 안 된다.
- 화자 줄: `speakers` 의 순서대로 `- <label>: "<first_lines>"` 를 한 줄씩 적는다.
- 마지막 줄: 화자 목록에 실제 `label` 들을 쉼표로 이어 적는다.
- `no_speech` 가 `true` 면 화자 줄과 마지막 줄 대신 `인식된 발화가 없습니다.` 를 적는다.

## 4. 이름을 바꾼다

사용자가 이름을 주면(예: "화자1은 김철수, 화자3은 박지민") 다시 분석하지 않고 이름만 바꾼다. 2단계의 `.json` 경로에 화자 번호마다 `--set` 을 하나씩 준다.

```bash
~/.local/share/asr/venv/bin/python "<스킬 디렉터리>/scripts/rename.py" "<json 경로>" --set "1=김철수" --set "3=박지민"
```

- `.json` 의 이름만 고치고 같은 이름의 `.md` 를 다시 만든다.
- 이름을 주지 않은 화자는 `화자 N` 으로 남는다.
- 종료 코드 2 는 없는 화자 번호나 잘못된 형식이다. stderr 메시지를 보여 주고 다시 물어본다.
- 끝나면 `.md` 경로와 바뀐 이름을 알린다. 사용자가 이름을 주지 않으면 그대로 끝낸다.
